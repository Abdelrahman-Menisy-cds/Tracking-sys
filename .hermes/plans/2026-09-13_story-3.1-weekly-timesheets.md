# Story 3.1 Implementation Plan — Weekly Timesheets (backend only)

Scope: Epic 3, Story 3.1 — create unique weekly timesheet + daily entries APIs.
Accepted spec sources: specs/timesheet-state-machine.md, product-policy-decisions item 4 &
6 (error envelope/idempotency), acceptance-criteria.md AC-06, epics.md 301-319.

Contract decisions (server-authoritative):
- Endpoints under /api/v1/timesheets/ (new Django app `timesheets` per
  architecture section 3 module list; depends only on identity, not reqs).
  - POST /api/v1/timesheets           → create sheet + entries atomically
    - 201 {"data": sheet}, 409 duplicate_week with existing {id, week_start}, 409
      idempotency_replay / idempotency_conflict, 422 validation.
    - Requires Idempotency-Key header (policy item 6).
    - Body: {week_start: "YYYY-MM-DD", entries: [{work_date, duration_minutes,
      unpaid_break_minutes}]}. entries optional, max 7, one per work_date (duration mode).
  - GET  /api/v1/timesheets/<id>       → owner/authorized detail (Story 3.1 scope: owner)
  - GET  /api/v1/timesheets            → owner-scoped paged list
- week_start: must be exactly organization timezone Monday (TimezoneConfig default "UTC"
  from settings; validation uses zoneinfo). Reject non-Monday/sunday mishmash with 422.
- Fields: duration_minutes int >= 0 (zero-minute entries allowed; negative rejected),
  unpaid_break_minutes int >= 0, entries keyed by work_date within week only, daily
  worked+break unbounded apart from worked > 24h → 422, total worked > 168h → 422,
  unpaid_break >= 0 and <= 24h*60 too, sum worked (Daily) <= 1440.
  No rounding, no automatic deductions, no timestamps in MVP (duration-only).
- Models (app timesheets): Timesheet, TimeEntry, TimesheetEvent (append-only),
  TimesheetCreateIdempotencyRecord (key hash + user unique), TimezoneConfig.
- Transactions: create does select_for_update on nothing conflicting; duplicate week check
  uses IntegrityError on unique (employee, week_start) plus pre-check; entries validated
  pre-insert; no partial writes.
- Error envelope: same pattern as config/api.error_payload with stable codes:
  duplicate_week, validation_error, idempotency_missing, idempotency_replay,
  idempotency_conflict, throttled, week_invalid.
- Totals: computed from minutes on serializer — total_worked_hours/minutes derived;
  raw minute integers stay canonical.

Tests (25-35): models/services/API tests in backend/timesheets/test_timesheets.py
covering happy create, totals fields, duplicate week safe conflict 409 (+existing ref for
owner), cross-user isolation 404, negative/invalid/out-of-week mismatch 422 + no mutation,
>24h day, timezone/DST-safe week boundary interpretation, zero-minutes allowed, idempotency
missing/replay/conflict/unique-constraint race, auth 401, CSRF 403, throttle 429,
ordering, pagination.
